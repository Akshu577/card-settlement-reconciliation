# Card Settlement Reconciliation & Dispute Analytics (SQL)

Daily card-operations work at a bank, done in SQL: match the bank's card-switch log against the card network's settlement file, classify every break, and track customer disputes against resolution SLAs.

I did this work by hand in Excel during my internship in the Electronic Banking Department at Rastriya Banijya Bank (member settlement reconciliation, dispute management, card issuance). This project rebuilds that workflow as repeatable SQL.

> **Data:** fully synthetic, generated by `src/generate_data.py` (20,000 card transactions over 3 months). No real customer data is used. The generator injects realistic breaks: transactions missing from settlement, amount differences, network duplicates, and orphan settlements.

## What the queries answer

| Query | Business question |
|---|---|
| `recon_summary` | How many approved transactions matched, and what is the net amount at risk for each break type? |
| `orphan_settlements` | What did the network settle that our switch has no record of? |
| `exceptions_by_channel` | Which channel (ATM, POS, e-commerce, mobile) produces the most breaks? |
| `dispute_kpis` | Dispute volume, average days to close, SLA breaches (>30 days) and refund rate for each reason |
| `monthly_dispute_trend` | Is dispute handling getting faster? |
| `repeat_dispute_cards` | Which cards should go to fraud review? |

SQL techniques used: CTEs, `LEFT JOIN` / `NOT EXISTS` anti-joins, conditional aggregation with `CASE`, date arithmetic, and `HAVING`.

## Sample findings

- **18,541 of 18,822** approved transactions matched cleanly (98.5%). **151** were missing from settlement, worth **8,440.54** in unsettled value.
- **ATM** has the highest exception rate (**1.99%**, against 1.22% for e-commerce), so ATM is where reconciliation effort should go first.
- **"Unrecognised transaction"** is the largest dispute category and the only one with many SLA breaches (5 closed after 30 days).

The full output is in [`reports/report.md`](reports/report.md).

## Run it

```bash
pip install -r requirements.txt
python src/generate_data.py   # builds card_ops.db (SQLite)
python src/run_report.py      # runs every query in sql/ and writes reports/report.md
```

The `.sql` files also run as-is in any SQLite client, such as DB Browser for SQLite or `sqlite3 card_ops.db < sql/reconciliation.sql`.
